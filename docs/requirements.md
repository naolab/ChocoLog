- ステータス: 初期方針確定・一部未決事項あり
- 画面設計: [画面構成・ワイヤーフレーム](./wireframes.md)

## 1. プロダクト概要

### 1.1 コンセプト

chocoZAP利用者が、その日に使った筋力系器具の重量・回数・セットと、有酸素系器具の運動時間を、ジム内でも素早く記録できるモバイルアプリ。

「運動を始める」「器具ごとの実績を残す」「今日の運動を振り返る」までを少ない操作で完了でき、短時間の運動習慣を続けやすくする。

### 1.2 仮称

**chocoLOG（チョコログ）**

名称は仮称。公開時は、chocoZAPおよびRIZAPの公式アプリ・提携アプリだと誤認されない名称、アイコン、説明文にする。商標やブランドガイドラインについて別途確認する。

### 1.3 提供形態

- フェーズ1: 自分・知人向けのiPhoneアプリ（TestFlight等を想定）
- フェーズ2: App Storeで一般公開
- フェーズ3: Androidアプリ
- 初期段階ではスマートフォン向けに最適化し、タブレット・Web版・Apple Watch版は対象外とする
- Flutterを採用し、iOS/Androidで可能な限りコードを共有する

## 2. 背景と解決したい課題

chocoZAPは短時間・日常利用と相性がよい一方、利用者が「今日どの器具を、どれくらいやったか」を自分向けに簡単に蓄積・比較する用途には、より記録に特化した体験を用意できる余地がある。

本アプリでは次の課題を解決する。

- ジム内でメモを取るのが面倒
- 前回の重量・回数・運動時間を思い出せない
- 週や月単位で、運動を継続できているか分かりにくい
- 店舗にある器具の中から、毎回使うものを素早く選びたい
- 短時間の運動でも達成感を得たい

公式chocoZAPアプリにも重量・回数を残す「運動記録」があるため、本アプリは単なる記録機能の有無ではなく、**セット単位の素早い入力、バックグラウンドタイマー、店舗器具への絞り込み、履歴比較のしやすさ**を中心的な価値とする。

## 3. プロダクト目標

### 3.1 MVPの目標

1. アプリ起動から3タップ程度で器具の記録を開始できる
2. 有酸素運動はタイマー計測と手入力のどちらからでも記録できる
3. 1回のトレーニング終了後、利用器具、時間、重量、回数、セットが履歴に残る
4. 前回の記録を見ながら、同じ内容を簡単に再記録できる
5. 週・月単位で運動回数と運動時間を確認できる
6. 通信状態が不安定な店舗内でも記録できる

### 3.2 成功指標（リリース後に計測）

- 初回記録完了率: 70%以上
- 記録開始までの時間中央値: 15秒以内
- 4週間後の継続利用率
- 週あたりの記録日数
- 開始したトレーニングの保存完了率: 90%以上

数値目標はベータテスト後に見直す。

## 4. 想定ユーザー

### 4.1 メインユーザー

- chocoZAPを週1〜4回利用する人
- 筋トレ初心者〜中級者
- 1回5〜30分程度の短時間利用が中心の人
- 高機能な筋トレアプリよりも、迷わず記録できることを重視する人

### 4.2 代表的な利用シーン

- 入店後、その日使う器具を選んでトレーニングを開始する
- 器具の使用開始時にタイマーを動かし、終了時に記録する
- トレーニング後に、筋力系のセット内容や有酸素系の時間をまとめて入力する
- 前回と同じメニューを呼び出し、重量だけ変更して記録する
- カレンダーから今月の運動日数を振り返る

## 6. 器具マスタ

公式サイトで案内されている以下の器具を初期マスタ候補とする。店舗によって設備が異なり、サービス・設備は変更される可能性があるため、ユーザー側で表示器具を絞り込める設計にする。

| カテゴリ | 器具 |
|---|---|
| 上半身 | ショルダープレス、チェストプレス、ラットプルダウン、バイセップスカール、ディップス |
| 体幹 | アブドミナルトレーナー、アブベンチ |
| 下半身 | レッグプレス、アダクション、アブダクション |
| 有酸素 | トレッドミル、バイク |

要件:

- 器具マスタはアプリアップデートなしでも将来更新できる構造を想定する
- 器具には名称、カテゴリ、対象部位、記録項目、表示順、有効/無効状態を持たせる
- 店舗差に対応するため「マイ器具」またはお気に入りで利用器具を絞り込める
- 公式サイトが画面表示に利用している店舗・器具データを取得し、お気に入り店舗の設置器具を初期表示する
- 店舗データの取得元は開発者向けに提供保証されたAPIではないため、外部データ取得処理をアプリ本体から分離する
- 取得失敗・仕様変更・データ欠損時は、全器具一覧またはユーザーが選んだ「マイ器具」を表示する
- 取得済みの店舗・器具情報を端末にキャッシュし、最終更新日時を表示する
- 店舗情報は参考情報として扱い、現地・公式アプリでの確認を促す
- 公式の器具画像はアプリへ転載せず、独自制作した器具イラストを使用する
- MVPではユーザー独自器具の追加は行わず、要望を確認して次期対応とする

## 7. 機能要件

### FR-01 トレーニング開始

- ホーム画面に「トレーニングを始める」を常時表示する
- 開始日時を自動記録する
- 前回のメニューを複製して開始できる
- セッション中にアプリを閉じても状態を保持する

### FR-02 器具選択

- カテゴリ、お気に入り、最近使った器具から選べる
- 器具名で検索できる
- 同じセッション内に複数器具を追加できる
- 同じ器具を複数回記録できる

### FR-03 有酸素運動・時間記録

- トレッドミル、バイク、クロストレーナー等の有酸素系器具に、開始・一時停止・完了できるタイマーを提供する
- 1分単位で手入力・修正できる
- タイマーを使わず、器具終了時または退店前にまとめて時間を入力できる
- セッション全体の経過時間と、器具ごとの運動時間を区別する
- 筋力系器具には運動時間を入力せず、重量・回数・セットのみを記録する
- タイマー稼働中は画面上で明確に状態を示す
- 誤操作防止のため、別器具のタイマー開始時には既存タイマーを停止または確認する
- アプリがバックグラウンドまたは画面ロック状態になっても、開始時刻と停止時刻の差分から正しい経過時間を算出する
- iOSがアプリ処理を停止しても計測結果が失われないよう、開始時刻とタイマー状態を即時保存する
- バックグラウンドで毎秒処理を継続することは要件とせず、復帰時に経過時間を再計算する
- タイマー停止忘れ対策として、設定可能な経過通知を検討する
- 対応端末ではLive Activityを使い、ロック画面とDynamic Islandに器具名、経過時間、状態を表示する
- Live Activityからアプリの計測画面へ戻れるようにする
- Live Activityを利用できない端末・OSでも、アプリ内タイマーは同等に記録できる

### FR-04 詳細記録

- 筋力系: セットごとに重量（kg）と回数を入力できる
- 基本操作は、1セット終了するたびにセットを追加する方式とする
- 器具の利用終了時に、同じ重量・回数の複数セットをまとめて追加できる
- まとめて追加した後も、各セットの重量・回数を個別に修正できる
- セットを追加・複製・削除・並べ替えできる
- 直前セットの重量と回数を初期値として引き継げる
- 器具選択時に、前回同じ器具を使った際の「重量 × 回数 × セット」を表示する
- 前回の全セットをワンタップで今回の入力へ複製できる
- 複製後は、各セットの重量・回数を個別に変更できる
- 重量は5kg刻みとし、5kg単位以外の値は保存しない
- 重量は数値入力に加えて、`−5kg` / `＋5kg` ボタンで変更できる
- `10kg`、`15kg`、`20kg`、`25kg`を初期クイック選択として表示する
- クイック選択候補は、将来的によく使う重量や前回値に応じて最適化できる構造にする
- 回数は数値入力に加えて、`−1回` / `＋1回`ボタンで変更できる
- `10回`、`12回`、`15回`を初期クイック選択として表示する
- セット保存後は直前セットの値を引き継いだ次セット入力状態へ進み、休憩タイマーは自動開始しない
- アブベンチ等の自重系器具は「自重」として扱い、重量入力を表示せず、回数・セットのみ記録する
- ウォームアップセット、通常セット等の種別はMVPでは持たず、必要性をベータで検証する
- 有酸素系: 時間を必須相当とし、距離（km）、速度（km/h）、傾斜、負荷を任意入力できる
- メモを任意入力できる
- 筋力系では重量・回数・セットを記録し、時間入力は設けない
- 有酸素系では「器具＋時間」だけで完了できる
- 前回値を初期候補として表示できる

### FR-05 店舗登録・店舗別器具

- 店名・駅名等から店舗を検索できる
- 1店舗以上を「よく行く店舗」として登録できる
- トレーニング開始時に今回の店舗を選択できる。店舗を選ばずに開始することもできる
- 選択した店舗の設置器具を器具選択画面の先頭に表示する
- 店舗ごとの器具名と台数を表示できる
- 店舗データが古い、または取得できない場合も、全器具一覧から記録を続けられる
- アプリ内から公式店舗ページへ移動できる

### FR-06 セッション完了

- 利用器具、筋力系のセット内容、有酸素系の器具別時間を確認して保存できる
- 未終了タイマーがある場合は警告する
- 保存後に本日の達成内容を簡潔に表示する
- 後から日時、器具、数値、メモを編集できる

### FR-07 履歴・カレンダー

- 日付ごとの記録有無をカレンダーで確認できる
- 日を選ぶとセッション一覧と詳細を表示する
- 直近の記録を新しい順で表示する
- 同じ日に複数回トレーニングした場合は、別セッションとして保存・表示する
- 記録を複製・編集・削除できる
- 削除前に確認を表示する

### FR-08 集計

- 週・月ごとの運動日数、セッション数、合計運動時間を表示する
- 有酸素系は器具別の累計時間と利用回数、筋力系は器具別の実施セット数と利用回数を表示する
- 筋力系は重量・回数の推移を閲覧できる
- データが少ない場合は空状態と次の行動を分かりやすく表示する

### FR-09 週目標・通知

- 1週間の目標トレーニング回数を設定できる
- 初回設定では週1回・2回・3回から選択でき、週2回を推奨値として表示する
- ホーム画面で「今週の実績 / 目標」を確認できる
- 週の開始曜日は月曜日を初期値とする
- ユーザーが曜日と時刻を指定してリマインダーを設定できる
- オンボーディングでリマインダー設定を案内し、設定せずにスキップすることもできる
- 通知許可は、価値を説明した後にOSダイアログを表示する
- 初期状態で過剰な通知を送らない
- 連続記録日数やバッジはMVPに含めない

### FR-10 データ保存

- MVPではアカウント登録なしで利用開始できる
- サーバー上のユーザー用データベースはMVPでは用意せず、端末内のローカルDBに保存する
- すべての記録操作をオフラインで完結できる
- アプリ更新後も記録を保持する
- 通常のiPhoneバックアップからアプリデータが復元される可能性はあるが、アプリ独自の復元機能としては保証しない
- 端末変更・アプリ削除時に確実な復元を提供するクラウド同期は次期対応とする
- 将来のクラウド同期を妨げないID・更新日時をデータに持たせる

## 9. UX・UI要件

### 9.1 デザイン方針

- 白を基調にし、黄色を主要アクセントとして使用する
- 明るく、気軽で、初心者が構えずに使える印象にする
- 主要操作は片手操作を想定して画面下部寄りに配置する
- 記録中の文字・ボタンは、運動中でも読みやすい大きさにする
- 黄色だけで状態を表現せず、文字・アイコン・形状も併用する
- ダークモードはMVP必須とせず、OS設定下でも表示が崩れないようにする

### 9.2 暫定カラーパレット

公式Webサイト上で確認できる色を参考にしつつ、完全な模倣ではなく独自性を持たせる。

| 用途 | 暫定色 |
|---|---|
| 背景 | `#FFFFFF` |
| メインアクセント候補 | `#FFEB00` |
| 淡いアクセント背景 | `#FFFDE0` |
| 主要テキスト | `#122939` |
| 補助テキスト | `#5F6870` |
| 境界線 | `#E0E0E0` |
| エラー | `#D30303` |

配色はプロトタイプ作成時にWCAGのコントラスト基準を確認する。黄色背景上の本文は白文字を避け、濃色を基本とする。

### 9.3 アクセシビリティ

- タップ領域は原則44×44pt以上
- Dynamic Typeによる文字拡大に対応する
- VoiceOver用ラベルを設定する
- 色覚だけに依存しない状態表現にする
- モーション低減設定を尊重する

## 11. 非機能要件

### 11.1 対応環境

- iOSの対応下限は実装開始時点の利用状況とフレームワーク要件から決定する
- Android対応を見据え、端末依存コードを分離する
- 日本語を初期言語とし、文字列は将来の多言語化が可能な形で管理する

### 11.2 性能・信頼性

- 通常起動後、ホームの主要情報を体感1秒程度で表示する
- 記録保存は即時に画面へ反映する
- アプリのバックグラウンド移行や強制終了後も進行中セッションを復元できる
- タイマーは画面更新回数ではなく時刻差分から算出し、バックグラウンドでもずれにくくする
- 保存失敗時に入力内容を失わず、再試行できる

### 11.3 プライバシー・セキュリティ

- MVPでは氏名、メールアドレス、位置情報など不要な個人情報を取得しない
- 利用分析を導入する場合は、取得項目と目的をプライバシーポリシーに明記する
- クラウド同期導入時は、通信暗号化、認証、退会・削除手段を用意する
- 健康情報に該当し得るデータとして慎重に扱う

## 13. 技術方針

iOS先行と将来のAndroid対応を両立するため、**Flutter** を採用する。Live ActivityはiOS固有機能のため、ActivityKitを利用するネイティブ連携部分として分離する。

- ローカルDBを正とするオフラインファースト構成
- ビジネスロジックとUIを分離する
- 器具マスタとユーザー記録を分離する
- 将来のクラウド同期に備え、UUIDと更新日時を採用する
- タイマー状態は永続化し、OS時刻を基準に復元する
- Live Activityの表示状態とアプリ内タイマーの保存状態を同期する
- クラッシュ解析・利用分析は、同意とプライバシーを考慮して導入する

## 14. MVP受け入れ条件

1. 初回起動からアカウント登録なしで記録を開始できる
2. 筋力系は1セット以上、有酸素系は1分以上の時間を持つセッションを保存できる
3. 筋力系器具では、セットごとに重量と回数を保存・編集できる
4. 同一内容の3セットを一括追加し、そのうち1セットだけを個別修正できる
5. 重量を10/15/20/25kgから選択でき、±5kgで変更できる。5kg単位以外は保存できない
6. 回数を10/12/15回から選択でき、±1回で変更できる
7. セット保存後に休憩タイマーが自動開始されず、次セットをすぐ入力できる
8. 前回の同一器具の全セットをワンタップで複製し、複製後に個別修正できる
9. 自重系器具では重量を求めず、回数とセットを保存できる
10. 有酸素系器具では時間と任意の距離等を保存できる
11. 筋力系器具では時間入力が表示されない
12. タイマー動作中、対応端末のロック画面・Dynamic IslandにLive Activityが表示される
13. 保存した内容が当日履歴とカレンダーに即時反映される
14. 過去記録を編集・複製・削除できる
15. オフライン状態でも開始、保存、閲覧、編集ができる
16. アプリを閉じても進行中タイマーを復元できる
17. 週の目標回数を設定し、ホームで達成状況を確認できる
18. 指定した曜日・時刻にリマインダー通知を受け取れる
19. 週・月の運動日数と合計時間が正しく集計される
20. VoiceOverで主要な記録フローを操作できる
21. お気に入り店舗を登録し、その店舗の設置器具で一覧を絞り込める
22. 店舗データを取得できない場合も、全器具一覧から記録できる
23. 同日に2回保存したトレーニングを、別々のセッションとして閲覧・編集できる
24. 初回設定で週1・2・3回から目標を選択でき、週2回が推奨表示される
25. オンボーディングでリマインダー設定をスキップしても利用開始できる

## 16. 決定事項

- 最初は自分・知人向けに配布し、将来App Storeで一般公開する
- 記録はタイマーと手入力の両方に対応する
- ランニング等のタイマーはバックグラウンド・画面ロックをまたいで計測する
- 有酸素系器具は時間中心、筋力系器具は重量・回数・セット中心とし、筋力系には時間を持たせない
- 重量・回数は初版からセット単位で扱う中心機能とする
- セット入力は1セットずつの追加を基本とし、同内容の複数セット一括追加にも対応する
- 重量は5kg刻みに限定し、数値入力、±5kg、10/15/20/25kgのクイック選択を提供する
- 回数は数値入力、±1回、10/12/15回のクイック選択を提供する
- 休憩タイマーの自動開始はMVPに含めない
- 前回の同一器具のセット内容を表示し、ワンタップで全セットを複製できるようにする
- 自重系器具は重量入力を表示せず、回数とセットを記録する
- Flutterを採用する
- Live ActivityをiOS MVPに含める
- 週の目標回数とリマインダーをMVPに含め、連続記録やバッジは後回しにする
- 黄色をアクセントにした、公式アプリと誤認されない独自デザインとする
- 同じ日に複数回トレーニングした場合は別セッションとして扱う
- 週目標は週1・2・3回から選び、週2回を推奨値とする
- リマインダー設定はオンボーディングで案内するが、スキップ可能とする
- 収益化方式は一般公開を検討する段階まで保留する
- ユーザー記録は初版では端末内に保存し、独自クラウド同期は後回しにする
- よく行く店舗と店舗別器具表示をMVPに含める。ただし外部データ取得不能時の代替手段を必須とする

## 17. 保留事項
